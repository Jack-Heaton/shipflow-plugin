# Review backend — Claude seats or headless Codex seats (shared reference)

**Scope:** this file configures headless GPT seats under a **Claude host**. For native
Codex, use `runtime.md` and `sf-runtime.mjs`: all roles use native GPT subagents, no
Claude pins or headless setup apply. The common stage/artifact contracts remain intact.
`HYBRID_MODE=codex` below means Claude-led hybrid, not Codex-native execution.

> Canonical spec for `SHIP_REVIEW_BACKEND`. Referenced by `ship-task` Stage 0, Stage 2,
> 3d, 3e and Stage 4 — and therefore by every skill that runs those stages by reference
> (`review-task-plan`, `review-task-code`, `fix-task`, the epic phase engine). The engine
> text in those stages is unchanged; this file is the substitution table applied
> wherever they say "spawn a reviewer" or "SendMessage a reviewer by `agent_id`".

## The switch

```
HYBRID_MODE=off      (default — today's behavior; nothing in this file applies)
HYBRID_MODE=review   (review seats run through `sf-codex` / `codex exec`; alias: SHIP_REVIEW_BACKEND=codex)
HYBRID_MODE=codex    (review + implementer + fixer/mop-up seats on Codex; Explore stays Claude — §Hybrid mode)
```

Read once in Stage 0 and recorded **once**, as `hybrid_mode=<off|review|codex>` plus the
legacy `review_backend=<claude|codex>` on the `preflight` event (`run-preflight.md`
§Review backend probe) — no separate `note` event. There is no per-seat *model* override
in the environment — which gate of record runs on which model family is a reviewed edit
to the pin list and §Seat tiers, not a flag. (`SF_CODEX_WRITE_SANDBOX` selects how writer
seats are sandboxed, not which model they run — §Hybrid mode.)

## Why (one paragraph)

Review and the plan loop are 30–68% of a run's sub-agent tokens (`ship-task/rationale.md`
§Cost shape); implementation is the cheap part. Every reviewer in the engine is already a
pure contract — spawn, write `review-<role>-r<N>.md` ending in a verdict line, the
orchestrator reads the file and addresses re-reviews by a recorded id — so the producer
can be swapped without touching the loops. Two model families reviewing the same change
also make the fix loop's "raised independently by ≥ 2 reviewers" convergence signal, and
`warm-closure.md`'s "independently formed positions", stronger claims than two spawns
that share priors. And `codex exec -s read-only` makes the read-only-reviewer rule
mechanical instead of prose.

## Seat tiers (which model and effort each Codex seat runs at)

Each Codex seat runs at a per-seat model and effort from `scripts/review-tiers.json`;
`sf-codex review` applies it to every **cold** seat. **The JSON file is the source of
truth; this table explains it.**

| Seat | Tier | Model / effort | Why |
|---|---|---|---|
| `plan-reviewer` (all rounds) | `frontier` | `gpt-6.2-sol` / medium | The highest-leverage gate — one spawn per round. |
| routed domain reviewer for the touched workspace (`frontend-reviewer`, `backend-reviewer`, `database-reviewer`, …) | `frontier` (`seats['*']`) | `gpt-6.2-sol` / medium | The gate of record on the code that changed. |
| `architecture` (baseline) | `standard` | `gpt-6.2-sol` / high | Structural reads. |
| `performance` (baseline) | `standard` | `gpt-6.2-sol` / high | Performance reads. |
| `plan-failure-over-time` (plan seat, round 1; a re-review resumes its thread) | `frontier` | `gpt-6.2-sol` / medium | The plan-stage twin of `failure-over-time`: the races a plan fixes in a sentence cost a fix round in code. |
| `failure-over-time` (baseline) | `frontier` | `gpt-6.2-sol` / medium | Interleaving reasoning on concurrency, queue, durable-step and retry changes — a gate on the failures tests do not reach. |
| `test-coverage-guardian` | `standard-light` | `gpt-6.2-sol` / medium | Coverage enumeration; severity calibration lives in its agent file §Output, so a lighter tier suffices. |
| any seat on the `regression` template (round ≥ 2, fix commits only) | `standard-light` | `gpt-6.2-sol` / medium | Fresh eyes on a small diff. `warm+cold-panel` re-runs the round-1 templates, so it keeps round-1 tiers. |
| `implementer`, `fixer`, `mopup-fixer` (`HYBRID_MODE=codex`) | `writer` | `gpt-6.2-sol` / low | Bounded by the plan or the findings; every commit is verified and then gated by review, the build and the acceptance checks. |

Every seat runs one model, `gpt-6.2-sol`, so a tier differs only in effort: `frontier` =
medium, the gates of record; `standard` = high, for structural and performance reads;
`standard-light` = medium, for enumeration and fix-commit-only reads; `writer` = low, for
the implementer, fixer and mop-up seats. Every tier pins `service_tier: "default"`, so no
seat runs on the priority service tier. Explore has no tier — it is never a Codex seat.
The `round2` cold-fallback template (a closure whose thread could not be resumed) carries
no template tier: it keeps the seat's own tier, because it re-reads the full prior
artifact rather than a fix diff.

**Resolution order** (`resolveTier` in `sf-codex.mjs`): explicit `--model` / `--effort` >
`--tier <name>` > `templates[<template>]` > `seats[<seat>]` > `seats['*']`. **A warm
continuation (`--resume`) never re-tiers** — each cold thread records what it was opened
with in `<CODEX_HOME>/sf-threads/<thread_id>.json`, and `resume` re-applies exactly that
(`-m` / `-c model_reasoning_effort`, both accepted by `codex exec resume`) rather than
trusting the run home or codex's own persistence, so a closure verdict is comparable with
the finding it closes; the result line reports `tier:"thread"` with the thread's model. `panel` forwards `--tier` / `--model` / `--effort` to every seat
identically (they are panel-wide experiment overrides — `panel --tier frontier` is the
pre-0.21 behavior); per-seat differences come only from the table.
`SF_CODEX_TIERS=<path>` swaps the whole table for an A/B run.

**What it does not change:** wall-clock. The panel envelope is set by the Claude seats
(security and UX) and the longest frontier seat; the demoted seats are a minority of the
run's Codex tokens, which bounds the saving.

**Ledger.** Each cold seat's `spawn` event and result line carry `tier=`, `model=<the
literal id actually run>` and `effort=`; `$ship-report`'s per-role `models` column renders
`<model>×n [<tier>×n]`, so the report shows the tier that ran, not the one the table
intended. A `--tier` typo (or a bad `--effort`) on `panel` is rejected before any seat
runs, and a seat whose own call is malformed reports `status:"usage-error"` (panel exit
1) — neither is ever a Claude-fallback signal.

**Revisit triggers** (measure per seat over the next handful of runs, `$ship-report`):
a `standard` seat that stops reopening partial fixes it used to reopen → back to
`frontier`; a `frontier` routed seat with zero CRITICAL/HIGH across many runs on small
diffs → `standard`; the regression template missing a fix-introduced defect that the
round-1 panel then catches → `standard`. Change the JSON and this table in one commit.

The pin list is exactly `security-reviewer,ux-consistency-lead` — pass it verbatim as
`sf-codex panel --pin`. **Express runs** keep `security-reviewer` on Claude as today and
drop the `architecture` baseline: pass `--routed-only` to `panel` (`sf-route` does not know
about express, so its roster file still lists `architecture`). `--routed-only` keeps
`failure-over-time` when the roster lists it — express never skips that seat.

## Hybrid mode (`HYBRID_MODE=off|review|codex`)

`HYBRID_MODE` supersedes `SHIP_REVIEW_BACKEND` as the one switch (the old variable is
kept as an alias: `SHIP_REVIEW_BACKEND=codex` ⇒ `HYBRID_MODE=review`). `review` is
everything above. `codex` additionally moves the seats whose input is the most bounded
artifact the pipeline produces and whose output is the most heavily gated:

| Seat | Claude (today) | `HYBRID_MODE=codex` | Tier | Guard the Claude path never had |
|---|---|---|---|---|
| **implementer** (3c, one per batch or per scratch worktree) | `sf-implementer` (opus) | `sf-codex implement` — `writer-prompts.md` §Implementer seat, seat body = `sf-implementer.md`; transport = app-server (`--transport exec` to opt out) | `writer` (`gpt-6.2-sol` / low, default service tier) | every reported commit sha is verified in `--baseline..HEAD` or the seat fails; numstat comes from git; `plan_gaps` tagged cosmetic/semantic |
| **fixer** (3e) and **mop-up** | `sf-fixer` (opus) | `sf-codex fix [--role mopup-fixer]` — `reviewer-prompts.md` §Fixer prompt, seat body = `sf-fixer.md`; transport = app-server (`--transport exec` to opt out) | `writer` (`gpt-6.2-sol` / low, default service tier) | same commit verification; `declined` findings carry evidence |
| speculative / prior-art / pre-implementation **Explore** (Stage 2, 3c), plan drafter / plan fixer, `security-reviewer`, `ux-consistency-lead` | Claude | **Claude (unchanged)** | — | — |

**Writers run with codex's sandbox bypassed** (`--dangerously-bypass-approvals-and-sandbox`,
the default `--write-sandbox yolo`): the worktree is the boundary — exactly the trust a
Claude `sf-implementer` already has, since Agent spawns are not sandboxed either. The
reason is mechanical, not preference: on a Linux host where bubblewrap cannot create user
namespaces the landlock backend refuses `workspace-write` (`permission profiles requiring
direct runtime enforcement are incompatible with --use-legacy-landlock`). Where codex's own
write sandbox works (macOS seatbelt,
bwrap-capable Linux) opt in with `SF_CODEX_WRITE_SANDBOX=workspace-write`. Either way the
seat is still bound by the worktree contract in its prompt and by the verification below.
**Never pass `--write-sandbox workspace-write` on a host where `home init` chose the
landlock backend**: the exec tool panics before any `command_execution` item is emitted, so
the seat burns a full model turn and comes back `status:"blind"` with `commands_run: 0`
(observed 2026-09-19: three implementer seats, zero commits, before a needless Claude
fallback). `sf-codex` now refuses that combination up front — exit 1, no spawn — when the
run home's `config.toml` carries `use_legacy_landlock = true`; the fix is to drop the flag,
not to fall back to Claude.

**Writer seat lifecycle (app-server).** A writer runs one `turn/start` on a fresh thread;
`sf-codex` consumes `item/completed`, `thread/tokenUsage/updated`, `thread/compacted` and
`turn/completed` live, which is the liveness `codex exec` never gave. Three clocks bound
the turn: **idle** (`--idle-min` / `SF_CODEX_IDLE_MIN`, default 10) interrupts a turn that
emits no `item/completed` for that long, so the window must exceed the longest legitimate
single command — a scoped type-check plus `vitest run --changed` on this monorepo; **wrap-up**
(`--wrapup-min` / `SF_CODEX_WRAPUP_MIN`, default 10) sends one `turn/steer` at wall − wrap-up
telling the seat to stop new work, commit what is gate-green and report — advisory, so the
wall interrupt still fires; **wall** (`--timeout-min`, default 40) interrupts the turn at the
budget. After any interrupt a bounded report turn (`--report-min` / `SF_CODEX_REPORT_MIN`,
default 5) on the same thread asks only for the JSON report of what is already committed, and
`sf-codex` still verifies every reported sha against git. The report turn (and the schema
re-ask turn) runs `turn/start sandboxPolicy:{type:"readOnly"}` — it only describes the tree, so
it keeps no write/exec access for the report budget, while git reads still run. The result line's `status` is the
outcome: `ok` (finished, no steer), `wrapped-up` (finished by itself after the steer) and
`interrupted-reported` (interrupted, then delivered a report) are all delivered — exit 0,
artifact on disk, unfinished acceptance rows carried as `DEFERRED` for the orchestrator to
re-batch; `failed` (exit 2) is a crash, a rate limit after retry, or an invalid report twice.
Sandbox mapping: `yolo` = `thread/start sandbox:"danger-full-access"` +
`turn/start sandboxPolicy:{type:"dangerFullAccess"}`; `workspace-write` = the `workspaceWrite`
policy with the worktree as the only writable root. `compactions=<n>` rides the result line
and the spawn event; `>1` (`oversized=true`) means the batch was larger than the seat could
hold — split the next one. `codex exec` remains the transport for the review, closure,
clarify and plan seats.

**A writer's report is a claim; the worktree is the evidence.** `sf-codex` runs `git log
<baseline>..HEAD` after the seat returns: a reported sha that is not there fails the seat
(`status:"failed"`, exit 2 → Claude fallback with the same prompt), `commits=` on the
ledger is git's count, and the rendered artifact's numstat is git's. Zero commits is
reported honestly (`commits:0`) and routes to ship-task's `empty-implementation` /
`implementer-failed` checkpoints as before. The blind-seat rule applies to writers too.

**Plan gaps are the measurement.** Each writer report lists every decision the plan (or
the findings) did not specify, tagged `semantic` (changed behaviour or an interface) or
`cosmetic`. `sf-codex` puts `plan_gaps_semantic=` / `plan_gaps_cosmetic=` on the spawn
event and the orchestrator sums them onto `batch-implement`. Semantic ≈ 0 over a handful
of runs is the evidence that the plan-path is bounded enough for a Sonnet-class
implementer; a rising count says the drafter — not the implementer — needs the tier.

## Fix direction (the orchestrator designs, the fixer executes)

Measured need (first `HYBRID_MODE=codex` run): the implementer, fed a 3-round-reviewed
plan, earned an A−; the same model as fixer, fed raw findings whose recommendations are
by design hypotheses, introduced 7 HIGHs in one round — a strict schema rejecting the
codebase's own stored shapes, a predicate locking out legacy users, a repo-wide config
bump. The gap was a missing design stage, not a weak executor.

The designer is the **orchestrator**, not another seat: at triage it already holds the
plan, explore reports, operator decisions and all reviewers' findings side by side, and
the direction is a short artifact of judgment it is already exercising. When bucket 1
holds any CRITICAL/HIGH or ≥ 5 findings, it writes `fix-direction-r<N>.md` (per finding:
approach, mandatory `verify_first` probes with invalidation criteria, constraints /
out-of-scope) — ship-task 3e step 2. The fixer treats it as binding; a probe outcome
that contradicts the approach stops that finding and reports, never improvises. Small
MEDIUM/LOW buckets and the mop-up skip it, so the cheap path stays cheap. Both backends
consume it: `sf-codex fix --direction <file>` substitutes the template's FIX DIRECTION
block (absent → an explicit "(none provided …)" line keeps the pre-0.23 semantics); a
Claude `sf-fixer` gets the same block pasted into its prompt.

The same principle runs one stage up and one stage over (both 0.23.0, ship-task Stage 2 /
3d / 3e): the orchestrator **adjudicates plan-review CRITICAL/HIGHs** against their cited
evidence before any plan-fixer pass (`refuted` findings die before costing a round),
**reads the diff while the panel runs** so triage and cross-seat dedupe are grounded in
code rather than finding prose, and **uses seat waits for the mechanical tail** (PR-body
draft, AC command table, closure tables, follow-up bodies).

**Stage 0.7 branch authorizations are not carried to Codex seats** and there is no flag
to add them: the inline-mode line is moot (inline mode has no `codex` CLI, so §Preflight
fails first) and the `# allow-protected-branch:` marker is a Claude `PreToolUse` guard
Codex never hits. Writer seats carry the worktree contract only.

**Complete commands** (`$WT_PATH`, `$ARTIFACT_DIR`, `$BATCH_BASELINE`, `$FIX_BASELINE`
are ship-task's variables; every seat writes its own ledger event when `RUN_LOG` is set):

| ship-task says | `HYBRID_MODE=codex` does |
|---|---|
| spawn one `sf-implementer` for the batch | write the batch's tasks verbatim to `$ARTIFACT_DIR/tasks-<batch>.md`; `BATCH_BASELINE=$(git -C "$WT_PATH" rev-parse HEAD)` (a full sha — `sf-codex` refuses a non-commit and freezes a symbolic ref, but capture it before the seat runs); `node "$SF/sf-codex.mjs" implement --tasks "$ARTIFACT_DIR/tasks-<batch>.md" --plan "$PLAN_PATH" --baseline "$BATCH_BASELINE" --batch <id> --explore "<comma-separated explore-*.md paths>" --cwd "$WT_PATH" --artifact "$ARTIFACT_DIR/implement-<batch>" --change-ref "<change ref>" --started "$T0"` (Bash, `run_in_background`; the `.md` artifact appearing is the completion signal). Parallel batches: one call per scratch worktree with that worktree's `--cwd` and the same `--baseline "$BATCH_BASELINE"` (scratch trees are cut at that sha — `scratch-worktree.md` `$BASE_SHA`). Read `commits`, `dirty`, `blockers`, `scope_violations`, `plan_gaps_*` from the result line |
| spawn one `sf-fixer` with the bucket | write the bucket (CRITICAL → LOW, grouped by file, recommendations and clarification answers included, ADJACENT marks kept) to `$ARTIFACT_DIR/findings-r<N>.md`; `node "$SF/sf-codex.mjs" fix --findings "$ARTIFACT_DIR/findings-r<N>.md" [--direction "$ARTIFACT_DIR/fix-direction-r<N>.md"] [--merged-items $MERGED] [--finding-ids '[…]'] [--epic-phase <id>] --baseline "$FIX_BASELINE" --round N --cwd "$WT_PATH" --artifact "$ARTIFACT_DIR/fix-r<N>" --change-ref "<change ref>" --started "$T0"` (Bash, **`run_in_background`**; the `fix-r<N>.md` artifact appearing is the completion signal — never `nohup … &` inside a foreground call, which returns at once and leaves nothing to wake the orchestrator, idling the run on fixers that have already finished) — `--direction` per §Fix direction (gated; the spawn event records `direction=`); `--merged-items` is the count of items merging more than one finding (the direction-review trigger and what `sf-log`'s `fixers_without_direction_review` check reads; the spawn event records `merged_items=`); `--finding-ids` is the JSON array of the bucket's item ids in a round after an `oscillation-stop` (validated as non-empty strings; recorded as `findings=` for `fixers_on_stopped_findings`), and `--epic-phase` stamps `epic_phase=` so a phase's round numbers do not collide with another's in the shared epic ledger; `declined` rows feed the closure tables as today |
| mop-up `sf-fixer` pass | capture `MOPUP_BASELINE=$(git -C "$WT_PATH" rev-parse HEAD)` first (the last fix round's commits must not be counted as mop-up), then the same `fix` command with `--role mopup-fixer --baseline "$MOPUP_BASELINE" --round <final round + 1> --artifact "$ARTIFACT_DIR/mopup"` (Bash, `run_in_background`, same completion signal) |
| `sf-log stage batch-implement …` | add `plan_gaps_semantic=<sum> plan_gaps_cosmetic=<sum>` from the implementer result line(s) (Claude implementers: count the report's "Decisions the plan did not specify" section). An app-server writer line with `oversized=true` (`compactions > 1`) means the batch outgrew the seat: split the next batch (≤ 4 steps) |
| a writer seat `status:"failed"` (any `crashed` value) or `"blind"` | **a writer fallback is never a clean re-run.** The fail line carries `commits_in_range` (commits already in `<baseline>..HEAD`) and `dirty` (uncommitted paths). `commits_in_range > 0` → decide once: **reset** (`git -C "$WT_PATH" reset --hard "$BATCH_BASELINE"`, then the Claude agent gets the whole tasks file / bucket) or **adopt** (hand the Claude agent `git log --oneline <baseline>..HEAD` as "already done — verify, do not redo"); reset is the default, adopt only when the artifact-less commits are plainly complete tasks. `dirty > 0` → the gated **adopt-dirty** path: when the scoped type-check AND `vitest run --changed <baseline>` per affected project (named files — never a whole-project run) pass on the dirty tree as it stands, commit it `[batch <id> — adopted after seat crash]` and continue (log `action=adopt-dirty`); gate-red → `git -C "$WT_PATH" checkout -- . && git -C "$WT_PATH" clean -fd` (the seat's half-work is not evidence of anything). Then spawn `sf-implementer` / `sf-fixer` and log `sf-log stage note event=codex-seat-fallback role=<role> commits_in_range=<n> action=<reset\|adopt\|adopt-dirty>` |
| a writer seat `status:"wrapped-up"` or `"interrupted-reported"` | **delivered, with work left over.** Read the artifact as for `ok`; every acceptance row the seat marked `DEFERRED` goes back into the next batch or fix round. `dirty > 0` (an interrupt leaves the edit it was in the middle of uncommitted) → the same gated adopt-dirty path: gate-green → commit `[batch <id> — adopted after seat interrupt]`, gate-red → `git -C "$WT_PATH" checkout -- . && git -C "$WT_PATH" clean -fd`. No Claude fallback spawn — the seat already delivered. Log `sf-log stage note event=codex-seat-partial role=<role> outcome=<outcome> compactions=<n> action=<adopt-dirty\|wipe\|none>`. adopt-dirty remains the exception: it fires only after a crash or an interrupt whose steer the seat did not act on. A seat that finished — `ok` or `wrapped-up` — is expected to leave a clean tree; when it does not, this path is what reads it. |

Everything downstream — routed review with its smoke type-check, triage, closure, cold pass, AC gate,
PR — is unchanged; reviewers still review the worktree, not the report.

| cold regression pass (`sf-route cold-roster` → `mode=warm`) | `node "$SF/sf-codex.mjs" panel --roster "$ARTIFACT_DIR/cold-roster-r<N>.json" --pin security-reviewer,ux-consistency-lead --template regression --cwd "$WT_PATH" --range "$FIX_BASELINE..$FIX_SHA" --artifact-dir "$ARTIFACT_DIR" --round N --change-ref "<change ref>" --started "$T0"` (save `cold-roster`'s JSON to that file first) |
| full round-1 panel, cold (`mode=warm+cold-panel`) | the 3d `panel` command again with `--round N` |
| `SendMessage(round-1 plan REVIEWER, targeted re-review)` | see §Plan review |
| "reviewers are read-only" (prose) | `codex exec -s read-only`; the seat never writes its artifact — `sf-codex` renders it |
| spawn event `model=session\|opus` | `model=<model id from the result line>` (e.g. `gpt-6.2-sol`), `tier=<seat tier>`, `effort=<reasoning effort>`, `agent_type=codex-exec`, `backend=codex` — written by `sf-codex` (§Seat tiers) |
| routed agent not installed → note the gap, continue | a seat whose result line says `status:"failed"` → **spawn that role on Claude** with the same template and log `sf-log stage note event=codex-seat-fallback role=<role>`. A seat is never left empty. |

Everything else in 3d/3e — triage buckets, `sf-route cold-roster`, the triage event,
the round-extension rules, the mop-up, `PushNotification` — is unchanged.

## Exit codes (`sf-codex review`)

| Exit | Result line | Meaning | Orchestrator response |
|---|---|---|---|
| 0 | `status:"ok"` | seat delivered; `.md` + `.json` on disk | read the artifact as for a Claude seat |
| 1 | none (stderr only) | **usage / configuration error** — missing or bad flag, seat file not found, renamed template heading | fix the call and re-run; **never** a fallback, never `codex-seat-fallback` — a wrong command is not a Codex failure |
| 2 | `status:"failed"` + `detail` | Codex could not deliver: auth, 429 after one retry, timeout, invalid JSON twice | spawn that role on Claude; log `codex-seat-fallback` |
| 3 | `status:"not-continuable"` | `--resume` could not continue the thread | the cold fallback template above, `path=cold-fallback` |
| 4 | none (stderr `review criteria unavailable`) | `review-plan/SKILL.md` or `scoring-rubric.md` unreadable | `CHECKPOINT_REQUIRED: plan-review-exhausted` (detail: review criteria unavailable) — the Claude seat would lack them too |

`panel` exits 2 only when **every** seat failed; partial failure exits 0 — read each
seat's `status`, never the panel's exit code.

A writer seat's `status` is its outcome, not a fixed `ok`: `wrapped-up` and
`interrupted-reported` are delivered at exit 0 alongside `ok` (§Hybrid mode); only `failed`
is exit 2.

## Findings table for closure (`--findings-table <path to a JSON file>`)

The flag takes a **file path**, never inline JSON. Write
`$ARTIFACT_DIR/closure-table-<name>-r<N>.json` first — one entry per finding of that
reviewer in the fix-now bucket, **declined rows included** (`warm-closure.md` §1 — a
decline is a claim its author verifies):

```json
[
  {"id":"SEC-1","summary":"token in URL","status":"fixed","commits":"abc123"},
  {"id":"SEC-2","summary":"missing tenant check","status":"declined","evidence":"<fixer's verbatim evidence>"}
]
```

Every id must come back verdicted; an id the reviewer omits is rendered `REOPENED`
("not verdicted by the reviewer") — the closure template's skeptical default. Verdicts
for ids not in the table, and duplicate verdicts, are ignored with a warning.

An entry may also carry `"item":"<item id>"` — the DEDUPE'd id the seat's finding was
merged into (`warm-closure.md` §3); the closure row's `reopened_ids` reports each reopened
finding as `item ?? id`, so the oscillation stop keys on the item, not the seat.


Both run in Bash with `run_in_background` (a round-1 plan review runs several minutes; the
Bash tool caps at 10 min) — the completion signal is the `.md` artifact appearing.

The seat reads `review-plan/SKILL.md` and `scoring-rubric.md` by path (the same by-path
rule as the Claude reviewer; `sf-codex` exits 4 if either is unreadable). The rendered
`plan-review-r<N>.md` is the criteria file's §Step 4 layout, so the drafter's warm fix
prompt reads what it reads today; the orchestrator takes `verdict` and the CRITICAL/HIGH
counts from the result line (or the `.json` sibling).

## Output contract and artifacts

Five schemas under `plugins/shipflow/schemas/`, passed with `--output-schema`. **Strict
structured outputs (the API-side rule, learned live on the first `HYBRID_MODE=codex` run):
every declared property must be listed in `required` and `additionalProperties` must be
`false`; an optional field is a nullable type (`"type": ["string","null"]`), never an
omission from `required` — the API rejects the whole schema otherwise and the seat fails
before it runs. `sf-codex.test.mjs` walks every schema for this.**

| Schema | Templates | Wrapper enforces |
|---|---|---|
| `review-findings.schema.json` | `round1`, `round2`, `regression` | verdict must be FAIL when any CRITICAL/HIGH exists (corrected in the artifact, `verdict_corrected:true` on the result line); a finding with `recommendation_cite: null` renders as "problem stated, fix not prescribed" |
| `review-closure.schema.json` | `closure`, `clarify` | every findings-table id verdicted (missing → REOPENED); `new_fix_introduced` renders under the `NEW (fix-introduced)` heading |
| `plan-review.schema.json` | `plan-r1`, `plan-rereview` | `overall_risk` = highest finding severity; any CRITICAL → "Stop and redesign"; "Stop and redesign" without a CRITICAL, or "Proceed as-is" with a HIGH/MEDIUM → "Proceed with modifications" |
| `implement-report.schema.json` | `implement`, `fix` | every reported commit sha must exist in `--baseline..HEAD` (else the seat fails); commit list and numstat are taken from git, not the report; `plan_gaps` counted by kind |

Every seat writes `<artifact>.md` (what 3e, the drafter and the fixer read — identical
in shape to a Claude seat's, verdict line included) and `<artifact>.json` (what the
orchestrator counts). `panel` names them `review-<name>-r<N>.md` where `<name>` is the
role minus `reviewer:` (`security-reviewer` → `review-security-r<N>.md`), plus one
`panel-<template>-r<N>.json` summary. Both sit in `$ARTIFACT_DIR` and commit with it on
tracked runs. A seat removes its own previous artifacts before running, so an artifact on
disk always means "delivered by this attempt". `--keep-prompt` also writes
`<artifact>.prompt.md` (off by default — the seat bodies are large).

The prompt is assembled from the **same shared template text** a Claude seat gets, with
the placeholders filled by the caller's flags (`--change-ref`, `--range`,
`--project-context`, `--prior-files`, `--prior-artifact`, `--findings-table`, `--plan`,
`--requirements`, `--fix-summary`): `sf-codex` locates the section by `## ` heading in
`reviewer-prompts.md` / `plan-prompts.md`, replaces `<worktree contract>` with a
read-only working-tree line and `<output contract>` with the JSON contract, drops the
"write the file / final message is one line" paragraphs (the model's final message *is*
the deliverable) and the `reply with exactly NOT-CONTINUABLE` signalling clause only
(the rule that follows it — never verdict from the fix diff alone — is kept, and restated
in the JSON contract), and prepends the seat body on cold spawns only — a resumed thread
already holds it. `node "$SF/sf-codex.mjs" templates` resolves every template for real
and exits 1 on the first broken heading or cut marker; run it after editing either file.

**Files whose structure `sf-codex` depends on** (check this list before editing any of
them): `reviewer-prompts.md` and `plan-prompts.md` (the `## ` headings and the trailing
`Write …` paragraphs of each reviewer template — plus, in `reviewer-prompts.md`, the
`## Fixer prompt` heading and its `<worktree contract + branch authorizations>` /
`<bucket-1 findings …finding>` / `[fix round <N> …]` placeholders); `writer-prompts.md`
(its two `## ` headings); `review-plan/SKILL.md` (its §Step 4
layout is what `plan-review-r<N>.md` reproduces, and its 3.1–3.11 dimension numbering is
hard-coded in `plan-review.schema.json`); `review-plan/scoring-rubric.md` (severity set
and verdict rule); the reviewer agent files under `shipflow/agents`,
`shipflow/agents` and a repo's `.claude/agents` (resolved by filename — a
rename makes the seat exit 1).

## Runtime and isolation

- **`CODEX_HOME` per run.** Stage 0 runs `export SF_CODEX_HOME=$(node "$SF/sf-codex.mjs" home init --run <run-id>)`
  → `~/.cache/sf-codex/<run-id>/` with `auth.json` symlinked from `~/.codex` (copied
  only if the symlink fails) and a generated `config.toml` (`model`,
  `model_reasoning_effort`, plus `service_tier` when the user's config sets one — all
  inherited from the user's top-level config; `gpt-6.2-sol` / `medium` when it names neither). Isolation buys a healthy private thread store for
  `resume` (the shared `~/.codex` store was found malformed in a devcontainer), no
  cross-talk with the user's interactive Codex threads in the same cwd, and a clean delete
  (`home gc --older-than 7` at Stage 4 — opportunistic: a checkpointed run never reaches
  Stage 4, so its home persists until the next run's gc; every seat bumps its home's mtime
  so gc measures the last seat, not `init`). It must not live under `/tmp` (verified: codex
  0.151 warns `Refusing to create helper binaries under temporary dir` and skips its PATH
  aliases) or inside the worktree (it holds credentials).
- **Sandbox** `-s read-only` for every review and plan seat — their only
  deliverable is the final message. Writer seats (`implement`, `fix`) instead run
  `--dangerously-bypass-approvals-and-sandbox` (or `-s workspace-write` via
  `SF_CODEX_WRITE_SANDBOX`) per §Hybrid mode — on the app-server transport these become the
  `thread/start` / `turn/start` sandbox shapes the §Hybrid mode lifecycle paragraph lists.
  Codex still loads the repo's `AGENTS.md` bridges and `.rules` — wanted.
  **Linux sandbox backend (load-bearing).** codex 0.151's Linux sandbox is bubblewrap,
  which needs unprivileged user namespaces; devcontainers commonly forbid them
  (`unshare -Ur` → EPERM) and then **every** command a seat runs fails with `bwrap: No
  permissions to create a new namespace` while the model keeps answering — a seat that
  reads nothing and still returns a verdict. Two defences: (1) `home init` probes
  `codex sandbox -- /bin/true`; when bwrap fails it verifies the deprecated landlock backend
  (`--enable use_legacy_landlock` — no namespaces needed, still read-only: a write to
  `/tmp` is denied) and writes `[features] use_legacy_landlock = true` into the run home's
  config so every seat and resume inherits it; neither working → exit 1 → `preflight-failed`.
  (2) `review` counts the seat's `command_execution` items and reports a seat that ran no
  command, or none successfully, as `status:"blind"` (exit 2 → Claude fallback), never as a
  verdict; `commands_run` / `commands_ok` ride the result line and the ledger. (3) A writer
  asked for `workspace-write` while the run home has the landlock flag is refused before the
  spawn (exit 1 — a call to fix, never a fallback), and a blind `workspace-write` writer on
  any host names the flag in its `detail` as the first thing to remove. (4) **Snapshot
  readers** — when neither backend starts (verified 2026-09-30 on codex 0.156–0.159: landlock
  alone panics with `filesystem-restricted execution requires bubblewrap to isolate app-server
  sockets`, and 0.155.1, the last release where it works, rejects `gpt-6.2-sol`), `home init`
  writes `sf-sandbox.json` (`{"reader":"snapshot"}`) into the run home instead of exiting 1.
  Every reader seat (review, closure, clarify, plan) then runs
  `--dangerously-bypass-approvals-and-sandbox` inside a disposable detached worktree of
  `--cwd` at the end of `--range` (else `HEAD`), created under the run home's `snapshots/`
  with the root `node_modules` linked in, and named in the prompt as the seat's working tree.
  After the seat's last turn, a moved `HEAD` or any new `git status` line in the snapshot
  discards the verdict as `status:"tampered"` (exit 2 → Claude fallback); the snapshot is
  removed either way. A warm turn resumes in a fresh snapshot (a resumed thread runs in the
  spawn cwd — verified on 0.159) and is told the new path. This detects writes to the
  snapshot; it cannot prevent a write to an absolute path elsewhere, through the linked
  `node_modules`, or to git refs the snapshot shares with every other worktree (a branch, a
  stash) — the read-only contract forbids all three, and a ref check would false-positive on
  the other runs committing in the same repository. The result line and ledger row carry `read_sandbox=snapshot` and
  `snapshot_sha`. `SF_CODEX_READ_SANDBOX=native|snapshot` overrides the marker;
  `SF_CODEX_SNAPSHOT_FALLBACK=0` restores the exit-1 stop. On a snapshot host the writer's
  report and JSON-retry turns keep full access (a read-only turn cannot run `git log` there).
- **Working directory** `-C $WT_PATH` on cold spawns; a resumed thread keeps its stored
  cwd (`codex exec resume --help` on 0.151 lists no `-C` / `-s`). **Sandbox on resume:**
  because `-s` cannot be passed (snapshot readers pass the bypass flag instead), the resumed turn takes the config-default sandbox —
  codex's default is `workspace-write`, which the landlock backend refuses, and on the first
  `HYBRID_MODE=codex` run every warm closure went blind that way. `home init` therefore pins
  `sandbox_mode = "read-only"` in the run home and `sf-codex` re-asserts it with
  `-c sandbox_mode="read-only"` on every resume (writers never resume).
- **Model, effort and service tier** come from §Seat tiers (`scripts/review-tiers.json`) for
  every cold seat; a tier may pin `service_tier` (every checked-in tier pins `default`) or leave
  it null, and a null one — like a null model/effort in a custom table — inherits the isolated
  home's `config.toml` (`model`, `model_reasoning_effort`, and the user's `service_tier` when
  set). A pinned tier value is re-asserted with `-c service_tier="…"`. `--model` / `--effort`
  / `--service-tier` / `--tier` on `sf-codex review` (or panel-wide on `panel`) are
  experiments, never silent defaults; a resumed thread keeps the model, effort and service
  tier it was opened with (from its sidecar).
- **Backgrounded runs and how to wait.** The Bash tool caps at 10 minutes and a round-1
  panel or plan review runs longer, so `panel` and the plan-review `review` run with
  `run_in_background`. `panel` writes **one JSON line per seat** as each finishes, then a
  final `{"panel":true,…}` summary line, and — the completion signal — the summary file
  `$ARTIFACT_DIR/panel-<template>-r<N>.json` containing every seat's result line under
  `results`. Wait for that file (`Monitor` it, or poll the task's output for the
  `{"panel":true` line) before entering 3e; read `thread_id` / `status` per seat from it.
  For a lone `review`, the `.md` artifact appearing is the signal. `--timeout-min`
  (default 40) is the wall budget: on an `exec` seat it kills the process group and reports
  `failed`; on an app-server writer seat it is the wall interrupt of the lifecycle in
  §Hybrid mode, after which the seat still gets a report turn.
- **Concurrency.** `panel --max-parallel` defaults to 4. Rate limits on a ChatGPT-plan
  login with several simultaneous `codex exec` processes are **unverified**; a 429 gets
  one 60 s retry, then the seat fails over to Claude.

## Preflight (Stage 0, only when backend=codex)

`run-preflight.md` §Review backend probe — CLI present and ≥ 0.151, logged in, `home init`
succeeded. Any failure → `CHECKPOINT_REQUIRED: preflight-failed` (detail: `review backend
codex: <reason>`). The operator asked for the Codex backend; downgrading the whole run to
Claude silently would make every later measurement a lie. (Per-seat failover mid-run is
different: it is logged, visible, and keeps the run moving.)

## Failure table

| Failure | Detected by | Response |
|---|---|---|
| CLI missing / too old / not logged in / home init fails | Stage 0 preflight | `CHECKPOINT_REQUIRED: preflight-failed` |
| malformed `sf-codex` call (missing flag, unknown seat, renamed heading) | exit 1, no result line | fix the call; not a Codex failure, no fallback |
| 429 / rate limit on a seat | `sf-codex` | one 60 s retry; then exit 2 `status:"failed"` → Claude spawn for that role, `note event=codex-seat-fallback` |
| `exec` seat exceeds `--timeout-min` | `sf-codex` | process group killed, exit 2 `status:"failed"`, same failover |
| app-server writer reaches the idle window or wall budget | `sf-codex` lifecycle | `turn/interrupt` + a report turn → `status:"interrupted-reported"`, delivered (exit 0); a dirty tree follows the §Hybrid mode writer-fallback row. Report turn fails or is invalid twice → `status:"failed"`, `crashed:false` → writer-fallback row |
| app-server process exits mid-turn | `sf-codex` (child exit) | `status:"failed"`, `crashed:true`, detected at once rather than at the wall → writer-fallback row |
| seat ran no command, or every command failed (sandbox cannot start) | `sf-codex` command stats | exit 2 `status:"blind"`, `note event=codex-seat-blind`, no artifact written → Claude spawn for that role; if it repeats across seats, stop and fix the sandbox (§Runtime) |
| final message fails the schema | `--output-schema` should prevent it; `sf-codex` validates anyway (including `anyOf` shapes) | one `resume` turn asking for valid JSON (skipped on `--ephemeral`); second failure → exit 2 |
| `--resume` cannot continue (`no rollout found`, thread-store error) | exit 3 | cold fallback template, `path=cold-fallback` — identical to Claude's `NOT-CONTINUABLE` path |
| review-plan criteria unreadable | exit 4 | `CHECKPOINT_REQUIRED: plan-review-exhausted` — never a Claude fallback |
| verdict inconsistent with findings | `sf-codex` | corrected in the artifact and flagged on the result line; never trusted from the model |
| run resumed on another machine (phase skills) | `thread_id` absent from that machine's home | exit 3 → cold fallback, as with any resumed run today |

## Accounting

`sf-codex review` writes its own `sf-log` event when `RUN_LOG` is exported (`--no-log`
suppresses it) — **the orchestrator logs nothing for a Codex seat, cold or warm**:

- cold templates (`round1`, `round2`, `regression`, `plan-r1`) → `spawn` with
  `role=<role> agent_type=codex-exec model=<model id> phase=<review|plan> backend=codex
  agent_id=<thread_id> tokens=… duration_ms=<wall> tokens_in/tokens_cached/tokens_out/tokens_reasoning
  commands_run=<n> commands_ok=<n>` (a delivered seat always has `commands_ok ≥ 1`);
- writer seats (`implement`, `fix`) → `spawn` with `agent_type=codex-app-server` (an
  `exec` writer stays `codex-exec`) and, on the app-server transport, `transport= outcome=
  compactions= oversized= idle_max_ms= steer_sent= interrupt_sent= attempts=<turns>`
  alongside `commits= dirty= plan_gaps_*`; a failed writer's `codex-seat-failed` note adds
  `transport= crashed= compactions=`. Usage is the last `thread/tokenUsage/updated.total`
  (cumulative for the thread), with the rollout-file fallback unchanged when a crash
  precedes the first usage notification;
- `closure` → `closure-exchange role=<role>:closure path=warm backend=codex` with the
  `findings_*` counts; `plan-rereview` → `closure-exchange role=plan-reviewer:rereview`;
  `clarify` → `clarify role=<role>:clarify`;
- a seat that fails → `note event=codex-seat-failed|codex-seat-not-continuable` with the
  `thread_id` and whatever usage it consumed, so a 40-minute timeout is not invisible.

The orchestrator still logs: `backend=claude` on the pinned seats' `spawn` events in a
codex-backed run, `codex-seat-fallback` when it re-spawns a failed seat on Claude, and the
`closure-exchange … path=cold-fallback` events for the cold templates it runs after an
exit 3. `$ship-report` prints a backend column and per-backend subtotal.

`tokens` = `tokens_in` + `tokens_out` summed over every model call the seat made (retry
turns included). **Codex `tokens_in` re-counts the transcript on every tool turn** (mostly
from cache), so a Codex seat's `tokens` is not comparable to a Claude seat's
`subagent_tokens` — compare by wall-clock and by `tokens_out` / `tokens_reasoning` until
the accountings are reconciled; the per-backend subtotal is a segmentation aid, not a
cost comparison.

Shape to expect: a round-1 panel or plan-review seat runs in minutes (hence the
backgrounding in §Backgrounded runs), a warm closure on the same thread in seconds. A
seat's verdict is trustworthy only with `commands_ok ≥ 1` — a seat that ran no command
still returns an answer, so §Runtime reports it as `blind` rather than as a verdict.

## Unverified (check after the first real runs)

- The wrap-up steer was acknowledged but not acted on in a 23 s probe; measure over real
  runs how often a writer lands `wrapped-up` (finished after the steer) versus
  `interrupted-reported` (had to be interrupted), which says whether the steer is earning
  its place or the wall is doing all the work.
- How long codex keeps `use_legacy_landlock` (deprecated); the probe fails loudly when it
  goes, and the fallback would then be a kernel/devcontainer that allows user namespaces.
- Whether Codex refreshes `auth.json` by rename (which would replace the symlink in the
  run home with a diverged copy that `gc` deletes) — after a run, check
  `<home>/auth.json` is still a symlink.
- The cause of the malformed shared thread store (isolation avoids it regardless).
- A repo's `.claude/agents` is a seat source, as it is for Claude Code — a branch under
  review can therefore ship a role file. Parity, not a new exposure; noted.

## What to measure before touching the pin list

Per seat over the next handful of codex-backed runs, from `$ship-report`: CRITICAL/HIGH
raised, closure `REOPENED` rate (does the seat hold its finding under a superficial
fix?), and failover count. A seat with zero CRITICAL/HIGH across many runs but high cost
is the same over-provisioning signal `model-tiering.md` already describes — the answer is
a tier change in §Seat tiers (first), then this file's pin list, never the env var. Only
then consider `--effort xhigh` on the plan seat (which runs at `high` — raise it only with
evidence that `high` missed a finding), the
OpenAI plugin's adversarial prompt as an extra regression seat, or moving
`security-reviewer`.
